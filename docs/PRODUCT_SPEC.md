Документ описывает продукт: что он делает, для кого и в каких границах. Как это реализуется — в технических
спецификациях.

## 1. Назначение

PlummyKnowledge — open-source **self-hosted** платформа корпоративной базы знаний с AI-интерфейсом. Она подключает
внутренние источники документов, индексирует их, даёт безопасный поиск и отвечает на вопросы сотрудников с
**проверяемыми цитатами** на исходные материалы (§1).

### Ценности (§1)

| Ценность | Что это значит для пользователя |
|---|---|
| Data ownership | Инсталляция принадлежит одной организации и работает на её серверах или в её облаке; документы, индексы, диалоги и настройки остаются у неё |
| Provider independence | Можно использовать облачные или **локальные** модели, отдельно выбирать embedding-модели |
| Source-grounded answers | Каждая цитата проверяется системой, а не принимается на веру от модели |
| Least privilege | Сотрудник видит только разрешённые базы знаний, документы и ассистентов |
| Deployability | Воспроизводимый запуск локально и на своём сервере |
| Extensibility | Новые модели, хранилища и источники добавляются без переделки продукта |

## 2. Целевая аудитория (§2)

- Малые и средние компании, которым нужна внутренняя AI-база знаний.
- Организации с требованиями к self-hosted/private deployment.
- Команды Google Workspace и Microsoft 365.
- Разработчики и интеграторы корпоративных AI-систем.

## 3. Термины

| Термин | Значение |
|---|---|
| Инсталляция | Один развёрнутый экземпляр PlummyKnowledge на сервере или в облаке организации-владельца. Одна инсталляция обслуживает одну организацию; нескольким организациям — несколько инсталляций ([ADR-012](adr/0012-single-organization-deployment.md)) |
| Knowledge Base (KB) | Набор документов из одного или нескольких источников с общим списком доступа |
| Document Source (источник) | Откуда приходят документы: локальная загрузка, Google Drive, Microsoft 365 |
| Assistant (ассистент) | Настроенный «собеседник»: инструкции, модель, подключённые KB, ограничения контекста |
| Цитата | Ссылка ответа на конкретный фрагмент документа, проверенная системой |
| Instance Settings | Настройки всей инсталляции; меняет владелец сервера |
| Application Settings | Настройки приложения; меняет Administrator через интерфейс в пределах настроек инсталляции |

## 4. Роли (§2)

| Роль | Что делает |
|---|---|
| Administrator | Пользователи, группы, роли, AI-провайдеры, источники, KB, ассистенты и настройки приложения; видит синхронизацию, ошибки, аудит и настройки инсталляции (сами настройки инсталляции меняются на сервере) |
| Knowledge Manager | Документы, базы знаний и синхронизация |
| Member | Работает с разрешёнными ассистентами |
| Auditor | Читает журнал аудита |

Владелец инсталляции — человек с доступом к серверу. Обычно он же первый Administrator, но это разные полномочия:
сетевые разрешения, хранилище, ключи и системные лимиты меняются только с доступом к серверу ([ADR-006](adr/0006-initial-setup-and-system-configuration.md)).

## 5. Основные сценарии

1. **Установка.** Владелец разворачивает систему через Docker Compose. При установке генерируется одноразовый
   код настройки; с ним владелец проходит мастер настройки и создаёт первого администратора. Без этого
   кода посторонний не может «занять» свежую инсталляцию (§2 сценарий 1, ADR-006).
2. **Модели.** Администратор подключает LLM и embedding-провайдера: облачного (OpenAI, Anthropic, OpenAI-compatible)
   или локального (Ollama, локальный OpenAI-compatible API). Локальный провайдер становится доступен после того, как
   владелец инсталляции явно разрешит его адрес (§2 сценарий 2, [ADR-007](adr/0007-network-access-and-local-llm.md)).
3. **Документы.** Загружает PDF/DOCX/XLSX или подключает Google Drive / Microsoft 365 (§2 сценарий 3). Все документы
   обрабатываются одинаково, независимо от источника ([ADR-008](adr/0008-unified-document-ingestion.md)).
4. **Индексация.** Система извлекает структуру, создаёт версии, фрагменты и векторные представления (§2 сценарий 4).
5. **Базы знаний и ассистенты.** Администратор создаёт KB, выдаёт к ним доступ пользователям и группам, создаёт
   ассистента и подключает к нему KB (§2 сценарий 5).
6. **Вопрос.** Сотрудник выбирает доступного ассистента и задаёт вопрос; система проверяет права, ищет только в
   разрешённых документах и вызывает модель (§2 сценарий 6).
7. **Ответ с цитатами.** Ответ приходит потоково, с цитатами; сотрудник открывает защищённый фрагмент источника внутри
   приложения (§2 сценарий 7).
8. **Администрирование.** Администратор видит состояние синхронизации, ошибки обработки и аудит (§2 сценарий 8).

## 6. Функциональные возможности MVP

### 6.1 Установка и настройка (§5, ADR-006)

- Запуск через Docker Compose с проверками готовности и понятной диагностикой ошибок старта.
- Мастер первоначальной настройки, защищённый одноразовым кодом; альтернатива — настройка только из командной
  строки сервера.
- Восстановление доступа администратора — только с доступом к серверу.
- Настройки инсталляции (видны Administrator, меняются на сервере) и настройки приложения (меняет Administrator,
  но не шире ограничений инсталляции).

### 6.2 Доступ (§5, ADR-005, ADR-012, ADR-013)

- Локальные учётные записи; вход, выход, управление сессиями; ограничение попыток входа. Самостоятельной
  регистрации нет: учётные записи создаёт администратор.
- Пользователи, группы, системные роли.
- Доступ к KB выдаётся пользователям и группам (чтение или управление).
- **Ассистент доступен сотруднику, только если у него есть доступ ко всем KB этого ассистента.** Если нет доступа
  хотя бы к одной — ассистента в списке нет. Изменение доступа к KB сразу меняет набор доступных ассистентов.
- Ассистент без подключённых KB виден только тем, кто настраивает ассистентов.

### 6.3 AI-провайдеры (§5, ADR-007)

- Подключение OpenAI, Anthropic, Ollama и OpenAI-compatible API; проверка соединения.
- Отдельный выбор embedding-модели (embedding profile); смена модели запускает переиндексацию.
- Ключи провайдеров хранятся зашифрованными и никогда не показываются после сохранения.
- Локальные модели работают так же, как облачные; их адрес разрешает владелец инсталляции.

### 6.4 Документы и источники (§5, §6, §7, ADR-008)

- Источники: локальная загрузка (первый источник), затем Google Drive и Microsoft 365.
- Форматы MVP: PDF, DOCX, XLSX, TXT, CSV, Markdown.
- Версии документов, статус обработки, повторная обработка, удаление.
- Удалённый документ сразу перестаёт участвовать в поиске и ответах.
- Синхронизация внешних источников вручную и по расписанию; переименования, перемещения и удаления в источнике
  отражаются в базе знаний.

### 6.5 Ассистенты и чат (§5, §6)

- Ассистент: инструкции, модель, embedding/retrieval profile, подключённые KB, ограничения контекста.
- Диалоги и история, потоковый ответ, остановка генерации.
- Цитаты на фрагменты документов (страница, раздел, лист/строка), просмотр фрагмента внутри приложения — без
  перехода по внешней ссылке Drive/SharePoint.
- Если в документах нет ответа, ассистент честно сообщает об этом.

### 6.6 Администрирование (§2, §10)

- Разделы: Login/Setup, Dashboard, Chat, Assistants, Knowledge Bases, Documents, Data Sources, Providers & Models,
  Users & Groups, Roles & Permissions, Jobs/Sync, Audit, System Settings.
- Журнал аудита критичных действий.

## 7. Ограничения продукта

| Ограничение | Почему | Источник |
|---|---|---|
| Доступ задаётся на уровне KB, а не отдельного документа | Document-level ACL вне MVP. В одну KB подключаются только источники, все документы которых могут видеть все участники KB | §8, ADR-004 |
| Ассистент доступен целиком или не доступен | Частичный доступ сделал бы ответы непредсказуемыми | ADR-005 |
| Выбор папки в Google Drive / Microsoft 365 не ограничивает права выданного токена | Так работает OAuth у провайдеров; система честно показывает фактические права | §7 |
| Адреса внутренней сети (в том числе локальных моделей) разрешает только владелец инсталляции | Защита от атак на внутреннюю сеть (SSRF) | §8, ADR-007 |
| Настройки инсталляции меняются только на сервере, с перезапуском | Компрометация web-учётной записи не должна ослаблять защиту инсталляции | ADR-006 |
| Модель не выполняет действий (нет tools) | Защита от prompt injection | §8 |
| Нет сложного OCR | Вне MVP | §2 |

## 8. Границы MVP

**Не входит в MVP (§2):** автономные агенты с действиями, визуальный workflow builder, billing, multi-region,
SAML/SCIM, полное наследование внешних document ACL, сложный OCR.

**Первый публичный релиз 0.1.0 (§19)** доказывает главную ценность: Docker Compose deployment; локальная
аутентификация и базовая KB-level авторизация; один или несколько LLM-провайдеров; загрузка PDF/DOCX и асинхронная
индексация; гибридный поиск и потоковый чат; проверяемые цитаты и просмотр источника в приложении; изоляция
данных по KB и пользователям, базовый аудит, документация и quick start.

**Дальнейшие релизы (§19):** 0.2.0 — XLSX/CSV и улучшения RAG; 0.3.0 — Google Drive; 0.4.0 — Microsoft 365;
0.5.0 — hardening/admin/backups; 1.0.0 — стабильные контракты и production readiness. Подробно —
[DEVELOPMENT_ROADMAP.md](DEVELOPMENT_ROADMAP.md).

## 9. Отложено на будущее

| Область | Возможности | Источник |
|---|---|---|
| Enterprise access | Document ACL, наследование прав, OIDC (следующая фаза), SAML, SCIM | §5, §14 |
| Доступ к ассистентам | Персональные разрешения, доступ через группы, публичные ассистенты для всех сотрудников, частичный доступ к KB | ADR-005 |
| RAG quality | Rerankers, OCR, table-aware retrieval, multimodal parsing, query rewriting | §14 |
| Platform | MCP, agent tools с allowlist/approval, webhooks, connector SDK, analytics, учёт потребления | §9, §14 |
| Администрирование | Изменение настроек инсталляции через интерфейс (требует отдельного решения) | ADR-006 |
| Аутентификация | Сброс пароля по email — при наличии почтовой инфраструктуры | §5 |

Billing и SaaS-сложность не планируются без подтверждённой стратегии (§14). Multi-tenancy (несколько организаций в
одной инсталляции) не планируется (ADR-012).

## 10. Как измеряется успех (§17)

Реальные установки, успешность установки, внедрения, контрибьюторы и качество issues — а не только stars.
Качество ответов — по evaluation-корпусу: Recall@K, MRR/nDCG, точность и покрытие цитат, groundedness, корректный
отказ при отсутствии ответа (§6).
