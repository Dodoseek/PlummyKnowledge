# ADR-014: List Pagination

- **Status:** Accepted
- **Date:** 2026-11-18

## Context

С этапа «Users & RBAC» появляются списки (`GET /users`, `GET /groups`), а дальше — документы, диалоги, jobs и audit
на десятки тысяч строк. [API_CONTRACTS.md §1.6](../API_CONTRACTS.md) предлагал cursor pagination как черновик;
формат входит в публичный API, поэтому фиксируется ADR (CLAUDE.md, §15 blueprint).

## Decision

1. **Cursor (keyset) pagination** для всех списков, которые могут расти: `?limit=25&cursor=<opaque>`.
   `limit` — от 1 до 100, по умолчанию 25. Offset-пагинации нет.
2. **Ответ:** `{ "items": [...], "next_cursor": "…" | null, "has_more": bool }`. Общего числа строк нет (на больших
   таблицах `count(*)` дорог и раскрывает объём данных).
3. **Курсор** — `base64url(JSON)` без padding: версия формата, ключ сортировки и значения последней строки
   (`[значение поля сортировки, id]`). Клиент считает его непрозрачным. Курсор не подписывается: он лишь задаёт
   позицию, а фильтры доступа всегда применяет сервер в SQL; подделанный курсор не открывает чужих данных.
4. **Порядок всегда детерминирован:** поле сортировки + `id` как tie-breaker, запрос
   `WHERE (sort_key, id) > (:k, :id)` (или `<` для убывания) по индексу.
5. **Allowlist:** у каждого endpoint свой список фильтров и полей сортировки (`sort=email`, `sort=-created_at`).
   Неизвестный query-параметр, недопустимое значение фильтра или сортировки, неверный курсор, курсор от другой
   сортировки → `422 invalid_query_parameter` с `errors[].field = "query.<name>"`. Значения никогда не
   подставляются в SQL строкой; поиск `q` экранирует `%`, `_` и `\`.
6. **Небольшие справочники** (роли, каталог permissions) возвращаются целиком без пагинации, но тоже в `items`.

## Alternatives

| Вариант | Почему отклонён |
|---|---|
| `offset`/`page` + `total` | Медленно на глубоких страницах, пропуски и дубли при вставках, `count(*)` на каждый запрос |
| Подписанный курсор (HMAC) | Курсор не является security boundary; подпись добавляет ключ и ротацию без выигрыша |
| Заголовок `Link` (RFC 8288) | Хуже для RTK Query; тело ответа проще и единообразно с остальным API |

## Consequences

- У сортируемых полей нужны индексы, совпадающие с порядком `(sort_key, id)`.
- Переход «на страницу N» невозможен — только «дальше»; UI показывает «Загрузить ещё».
- Изменение формата курсора — новая версия внутри курсора; старые курсоры дают `422`, клиент начинает сначала.

## Security considerations

- Пагинация не заменяет авторизацию: каждая страница строится запросом с фильтрами доступа.
- Ограничение `limit ≤ 100` и запрет неизвестных параметров ограничивают нагрузку и поверхность ввода.
